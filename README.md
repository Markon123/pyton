# ОренКод · цифровая платформа ФСП Оренбургской области

Проект по расширенному кейсу ФСП: кабинеты спортсмена, тренера, судьи, федерации и министерства, полный цикл соревнования, реестр, квалификации, рейтинг, сборная, отчёты и дополнительные модули Д1–Д12. Интерфейс на русском языке, работает в браузере на компьютере и телефоне. Все демонстрационные люди, организации, результаты, приказы, пороги и суммы вымышлены.

Исходники: [Markon123/pyton](https://github.com/Markon123/pyton). [Скачать ZIP](https://github.com/Markon123/pyton/archive/refs/heads/main.zip). Это ссылки на код; публичный сайт автоматически не создаётся.

**Состояние по ТЗ:** [аудит от 28.10.2026](docs/tz-audit-2026-10-28.md) выявил ошибки и незакрытые пункты. Базовые сценарии работают и 147 тестов проходят на SQLite/PostgreSQL, но это ещё не полное соответствие ТЗ.

**Чекпоинт № 2:** [видео полного сценария — MP4, 2:05](https://github.com/Markon123/pyton/raw/refs/heads/main/docs/checkpoint-2.mp4), [полученный протокол — PDF](docs/checkpoint-2-protocol.pdf), [порядок демонстрации](docs/checkpoint-2.md). В видео новый турнир проходит путь от создания и заявки отдельного спортсмена до публикации результата в его истории.

## Самый простой запуск на Windows

1. Скачайте ZIP и **полностью распакуйте** его: правая кнопка → «Извлечь всё».
2. Установите Python 3.12 или новее с [python.org](https://www.python.org/downloads/windows/). Включите **Add Python to PATH**.
3. В распакованной папке `pyton-main` дважды щёлкните **`start-demo.bat`**.
4. Дождитесь первой установки пакетов. Браузер откроется после проверки приложения; окно запуска оставьте открытым.
5. Войдите: **`federation` / `FspDemo2026!`**.

macOS/Linux: из распакованной папки выполните `bash start-demo.sh`. Для первой установки нужен интернет. Лаунчер создаёт `.venv`, применяет миграции и добавляет демонстрационные данные всех модулей. Повторный запуск сохраняет существующие записи. Если возникла ошибка, окно Windows останется открытым; подробности — `.local/launcher.log` и [инструкция запуска](docs/local-launch.md).

Нативные проверки Windows выполняет отдельный workflow GitHub Actions; результат смотрите на вкладке Actions конкретного коммита. Наличие файла workflow не является подтверждением его успешного удалённого запуска.

## Демо-аккаунты

Пароль всех демонстрационных аккаунтов — **`FspDemo2026!`**.

| Логин | Возможности |
| --- | --- |
| `federation` | Несколько ролей: управление соревнованиями, заявками, реестром, критериями, документами и сборной |
| `athlete` | Профиль, заявки, результаты, разряд, тренерские связи, путь спортсмена и QR-справки |
| `coach` | Подтверждённые спортсмены, заявки и разряды по дисциплинам связи, группы и нормативы |
| `judge` | Категория, назначения и документы о судействе |
| `ministry` | Кабинет министерства: чтение календаря, отчётов и состава сборной без изменения данных |

Активную роль переключают в верхней панели без повторного входа. Права проверяются по выбранной роли, включая права на конкретного спортсмена и дисциплину. Самостоятельная регистрация не выдаёт роль федерации или министерства. Демо-аккаунты не являются техническими администраторами Django.

## Запуск для разработки

Python 3.12+, без отдельного frontend-сервера:

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate
# macOS/Linux:
. .venv/bin/activate
python -m pip install -r requirements.txt
python manage.py migrate --noinput
python manage.py seed_full_demo
python manage.py collectstatic --noinput
python manage.py runserver
```

Локальное приложение использует порт `8000`. `GET /health/` проверяет доступ к БД. Часовой пояс — `Asia/Yekaterinburg`. `seed_full_demo` добавляет справочники, базовые записи, группы, нормативы, правила премий, критерии развития и тестовый OIDC-клиент; существующие данные и пароли не сбрасываются.

Для повторяемой настройки: `FSP_SEED_DEMO=1 bash scripts/setup.sh`, затем `bash scripts/start.sh`. По умолчанию используется `.venv`; в подготовленной облачной среде задайте `FSP_VENV_DIR=/workspace/.venvs/pyton`. Используйте существующий checkout: дополнительное Git worktree для изолированной облачной задачи не требуется.

Для чистой базы без фикстур: после миграций выполните `python manage.py prepare_project` — только начальные справочники и макеты. Технический администратор создаётся отдельно через `python manage.py createsuperuser`; ему нужно явно назначить профиль и бизнес-роли для работы в кабинетах. Не используйте техническую админку вместо бизнес-процессов: прямые ORM/admin-правки не проходят через их аудит и проверки активной роли.

## Проверка

В активированном окружении:

```bash
python manage.py check
python manage.py makemigrations --check --dry-run
python manage.py test
```

Тесты используют отдельную БД. Проверяют реальные процессы, ограничения ролей, данные документов, OIDC/PKCE, API, зачисление и нормативы, апелляции, премии, публичную проверку QR и почтовый транспорт. Для переноса зависимостей используются закреплённые версии `requirements.txt`.

В репозитории есть CI для SQLite на Windows/Ubuntu и PostgreSQL. Успешность удалённого CI, новой машины и реального внешнего SMTP проверяется отдельно; наличие конфигурации не подтверждает эти результаты.

## Почта, расписание и размещение

По умолчанию письма сохраняются локально в `.local/mail/`; это не отправка в реальный внешний ящик. SMTP-транспорт и повторная отправка реализованы, а [проверка почты](docs/mail.md) использует отдельный SMTP-приёмник. Для рабочей доставки нужны реквизиты разрешённого почтового сервера и подтверждение получателя. Не отправляйте пароли и ключи в чат или Git.

Периодические задачи запускаются отдельным процессом:

```bash
python manage.py run_scheduler --interval 60
```

Он обрабатывает очереди почты/вебхуков и ежедневные напоминания. Для одного прохода используйте `--once`. Живые процессы и планировщик не сохраняются в облачном снимке; их запускают заново после восстановления.

Для запуска с PostgreSQL, Gunicorn, планировщиком и демонстрационным SMTP-приёмником предусмотрены Docker и Compose. Команды, HTTPS, секреты, статика и восстановление БД — в [инструкции развёртывания](docs/deployment.md). Публичный хостинг и домен не предоставлены: GitHub хранит исходники и не запускает сервер Django.

## Данные и условия внедрения

- Локальные SQLite, защищённые загрузки, журналы и OIDC-ключ находятся в `.local/` и исключены из Git. Для PostgreSQL задаётся `DATABASE_URL`, для отдельного файла SQLite — `DATABASE_PATH`.
- Произвольный `.env` обычный Python-запуск не читает: экспортируйте переменные или используйте средства хостинга. Docker Compose понимает свой `--env-file`; образцы не содержат реальных секретов.
- Численность использует исторические интервалы зачислений; периоды до первого зачисления в каждой дисциплине учитываются по прежнему интервалу начала/окончания занятий. В этих старых данных организация и муниципалитет соответствуют текущему профилю; их источник явно отмечен как legacy. Новое зачисление не стирает прежнюю численность.
- Пороги подготовки, критерии кандидатов на разряды и суммы премий в фикстурах демонстрационные. Перед применением федерация должна внести действующие значения из нормативных источников и проверить дополнительные условия. Автоматическая подсветка не присваивает разряд и не назначает государственную премию.
- Утверждённые заказчиком бланки не приложены. Настраиваемые шапки и структурированные выгрузки не заменяют согласование официальных форм, подписей и электронной подписи.
- QR подтверждает запись платформы. Для доступности проверки вне локального компьютера задайте действительный `PUBLIC_BASE_URL` размещённого сайта. Публичная страница показывает только инициалы и результат.
- Для внедрения необходимы чистые рабочие данные, отдельные секреты и домены, HTTPS, SMTP, резервные копии, мониторинг и проверка требований к ПДн. Демонстрационные согласия не являются юридической экспертизой.

Резервная копия: `python manage.py backup_database`. Проверяйте восстановление в отдельную пустую БД и храните копии БД, защищённых файлов и OIDC-ключа вне машины. Подробности — в [инструкции развёртывания](docs/deployment.md).
