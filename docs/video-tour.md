# Подробная видеодемонстрация ОренКод

[Открыть или скачать MP4 с русской озвучкой](https://github.com/Markon123/pyton/raw/refs/heads/main/docs/video-tour.mp4).

Запись выполнена в работающем приложении на отдельной базе с вымышленными участниками, организациями и результатами. Используются настоящие формы и скачанные из приложения документы. Титры и озвучка поясняют действия; экраны приложения и ответы сервера не подменяются.

## Что показано

- Рейтинг → карточка спортсмена → выбор участников → сохранение сборной → итоговый список и PDF.
- Поиск в реестре → карточка → динамика численности за два года → экспорт и открытие XLSX.
- Опубликованный протокол и персональный отчёт спортсмена: скачивание и просмотр PDF.
- Кабинет министерства, календарь, сводные отчёты и документы. Спортивные данные доступны для чтения; управление аккаунтами федераций — отдельное полномочие главного аккаунта.
- Д1: настоящий вход через ФСП ID / OpenID Connect, согласие пользователя, проверенный ответ и отзыв разрешения.
- Д2: консоль интеграций, реальный CSV-импорт результатов, схема API и настройки вебхуков.
- Д3: организация → группа тренера → создание занятия → сохранение посещаемости.
- Д4: справочник нормативов → внесение результата → сравнение с порогом → проверка готовности к аттестации.
- Д5: подача апелляции спортсменом и перевод федерацией на рассмотрение с мотивировкой.
- Д6: показатели региона и смена отчётного периода.
- Д7: путь спортсмена, следующая ступень, подходящие старты и справочник.
- Д8: основания кандидатов, условные правила премий и ходатайство.
- Д9 включён в показ министерства, без повторной экскурсии по тем же отчётам.
- Д10: выдача PDF-справки с QR и публичная проверка уникального номера без входа.
- Д11: навигатор новичка → дисциплины, организации, старты → форма регистрации.
- Д12: собственные назначения судьи, скачанные состав коллегии и личная история судейства.
- Итоговые роли: изменение обычной роли федерацией; кабинеты спортсмена, тренера, судьи и министерства; заявка судьи на категорию; возврат в федерацию.

## Соответствие текущему проекту

ФСП ID — отдельный OIDC-процесс. Номер карточки участника не выдаётся за ФСП ID; поиск реестра по идентификатору не реализован и не показан.

Тренер управляет подтверждёнными спортсменами по дисциплине и своими учебными группами. Региональную сборную формирует федерация. Судья подаёт заявку на судейскую категорию.

Внешний партнёр не подключён: в видео показаны работающий локальный импорт и настройки интеграции. Доставка реальному получателю и получение письма во внешнем ящике не заявляются. Встроенный OIDC-клиент работает локально в режиме разработки.

Тестовые нормативы и правила премий показаны как условные. Официальные источники и бланки требуют согласования перед эксплуатацией. QR в этой записи проверяется на том же локальном стенде; проверка с другого устройства требует доступного ему адреса.

## Воспроизвести запись

Это дополнительные инструменты записи, обычному запуску сайта они не нужны. Требуются Python с зависимостями проекта, Node.js, Playwright, Chromium, FFmpeg/ffprobe и pdftoppm. Скрипты рассчитаны на локальную изолированную среду.

Из корня проекта в активированном Python-окружении:

```bash
python scripts/prepare_video_tour.py --base-url http://127.0.0.1:8018
npm install --prefix .local/checkpoint2-tools playwright@1.58.2
PLAYWRIGHT_BROWSERS_PATH="$PWD/.local/checkpoint2-tools/browsers" node .local/checkpoint2-tools/node_modules/playwright/cli.js install ffmpeg
PYTHONPATH="$PWD/.local/video-tour" DJANGO_SETTINGS_MODULE=video_settings python manage.py runserver 127.0.0.1:8018 --noreload
```

Подготовка разрешена только внутри .local/video-tour/*.sqlite3. Пароль тестовых аккаунтов создаётся случайно в закрытом .local/video-tour/credentials.json и не выводится. Загрузки, почта, OIDC-ключ и исходная копия базы находятся в том же игнорируемом каталоге. Рабочая .local/platform.sqlite3 не используется и не изменяется.

Для проверки сценария без записи из другого терминала:

```bash
VIDEO_TOUR_RECORD=0 VIDEO_TOUR_HOLD_SCALE=0 node scripts/record_video_tour.cjs
```

Проверка выполняет реальные действия и изменяет только тестовую базу. Перед финальной записью остановите именно этот тестовый сервер и восстановите platform.sqlite3 из baseline.sqlite3 внутри .local/video-tour, затем вновь запустите сервер. Не подставляйте пути рабочей базы. Новый сквозной прогон должен начинаться с подготовленного состояния без созданной в проверке апелляции.

Результаты проверки: .local/video-tour/recording/evidence.json; файлы из приложения: recording/artifacts/. Для Python просмотрщика XLSX можно задать VIDEO_TOUR_PYTHON, для Chromium — CHROMIUM_PATH, для Playwright — PLAYWRIGHT_MODULE, для адреса тестового сервера — VIDEO_BASE_URL.

## Русская озвучка

Озвучка синтезирована локально по тексту пояснений. Пароли, токены и закрытые данные не отправляются в речевые сервисы. Модель и зависимости TTS не включены в ZIP проекта.

Установите отдельные инструменты, не меняя requirements.txt приложения:

```bash
python -m venv .local/video-tour/tts-venv
.local/video-tour/tts-venv/bin/python -m pip install piper-tts==1.8.0 sherpa-onnx==2.0.1 numpy
```

Модель ru_RU-ruslan-medium берётся из [релиза sherpa-onnx](https://github.com/k2-fsa/sherpa-onnx/releases/download/tts-models/vits-piper-ru_RU-ruslan-medium.tar.bz2). Распакуйте каталог vits-piper-ru_RU-ruslan-medium в .local/video-tour/tts-model/. Если выбран другой путь, передайте --model-dir скрипту; доступные параметры показывает --help.

После подготовительного прохода создайте кэш озвучки:

```bash
.local/video-tour/tts-venv/bin/python scripts/narrate_video_tour.py
```

Индекс narration-index.json содержит длительности фраз. Финальная запись ждёт окончания каждой реплики:

```bash
VIDEO_TOUR_RECORD=1 VIDEO_TOUR_HOLD_SCALE=1 VIDEO_TOUR_REQUIRE_NARRATION=1 node scripts/record_video_tour.cjs
.local/video-tour/tts-venv/bin/python scripts/narrate_video_tour.py --mix
python scripts/package_video_tour.py
```

Для изменённого текста сначала обновите кэш. Скрипт проверяет отсутствие наложений реплик и собирает narration.wav по фактическим отметкам времени. Запись сохраняется в video-tour.webm; пакетировщик проверяет полный проход, семь скачанных документов и дорожку озвучки, затем создаёт MP4 H.264/AAC с главами и русскими субтитрами. Повторная упаковка готового файла требует явного --overwrite.

Голос и условия использования аудиодорожки: [атрибуция и лицензия](video-tour-audio-license.md). Исходники записи: [основной скрипт](../scripts/record_video_tour.cjs), [подготовка тестовых данных](../scripts/prepare_video_tour.py), [локальный синтез речи](../scripts/narrate_video_tour.py).
