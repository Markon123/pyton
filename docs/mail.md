# Почтовая очередь и внешний канал уведомлений

Внутренние уведомления всегда сохраняются в БД. После завершения транзакции приложение пробует передать письмо текущему почтовому транспорту; неуспешная отправка не отменяет действие пользователя. На периодических задачах работает `process_outbox`, который повторяет временные сбои. Один запуск:

```bash
python manage.py process_outbox --limit 100
```

В `Notification` сохраняются состояние `queued / processing / local / sent / failed / skipped`, число попыток, безопасный класс ошибки и время повтора. `local` означает файловый, консольный или тестовый backend — это **не внешняя доставка**. `sent` ставится только после принятия письма SMTP-сервером. Это подтверждает передачу серверу, но не прочтение и не попадание в конечный почтовый ящик. Пустой адрес получает `skipped`. Старое поле `email_sent` означает принятие выбранным backend, поэтому для отчёта о внешнем канале используется именно состояние `sent`.

Сбои повторяются с увеличением задержки (1 минута, 2 минуты и далее до часа), максимум 8 попыток. Состояние `processing` имеет двухминутную аренду: после аварии обработчика задача станет доступной снова. Параллельные обработчики используют условное обновление БД и не выполняют обычную отправку одновременно. Гарантия — **как минимум одна попытка доставки**: если процесс завершится между SMTP ACK и фиксацией результата в БД, возможен дубликат. Сквозная гарантия exactly-once для SMTP не заявляется.

После исправления SMTP-настроек можно намеренно повторить локальные письма:

```bash
python manage.py process_outbox --retry-local
```

Этот флаг отправляет ранее локально сформированные письма текущему backend; сначала убедитесь, что адресаты правильные. Реальные реквизиты никогда не помещайте в Git или чат.

Для ручного возобновления `failed`, включая задачи с исчерпанными восемью попытками, после исправления причины используйте `python manage.py process_outbox --retry-failed`. Уже принятые SMTP-сервером письма повторно не отправляются.

## Проверка транспорта без чужих почтовых ящиков

`python manage.py test federation.test_mail_delivery` поднимает настоящий SMTP-сервер `aiosmtpd` на свободном порту этой машины, передаёт уведомление через SMTP-клиент Django и проверяет адрес получателя, MIME-тему и русский текст. Проверяются также сбой, отложенный повтор, аренда задачи и отсутствие повторной отправки уже принятого сообщения. Тест ничего не отправляет во внешнюю сеть.

Для демонстрации между контейнерами предусмотрен Mailpit:

```bash
docker compose --env-file deployment/demo.env --profile mail up --build -d
```

Приложение использует SMTP на внутреннем сервисе `mailpit:1025`; его интерфейс просмотра почты привязан к порту `8025` только на этой машине. Откройте этот локальный порт браузером. Войдите в приложение и измените статус заявки: появится внутреннее уведомление и отдельное SMTP-письмо в Mailpit. Это проверяемый внешний по отношению к приложению транспорт, **не отправка на реальные внешние адреса**.

## Реальный SMTP

Задайте через безопасные настройки процесса `EMAIL_BACKEND=django.core.mail.backends.smtp.EmailBackend`, `EMAIL_HOST`, `EMAIL_PORT`, `EMAIL_HOST_USER`, `EMAIL_HOST_PASSWORD`, `EMAIL_USE_TLS=1`, `DEFAULT_FROM_EMAIL`. Настройки загружаются из окружения, произвольный `.env` при обычном запуске Python не читается; Docker Compose умеет читать свой `--env-file`. TLS-проверки сертификатов не отключаются. На работающей облачной машине реквизиты SMTP отсутствовали, поэтому подтверждение доставки в настоящий внешний ящик требует настроенного сервера и разрешённого тестового получателя. Логи не печатают пароли, процессное окружение или текст SMTP-ошибок с реквизитами.

## Регулярная работа

```bash
python manage.py run_scheduler --interval 60
```

Один экземпляр планировщика проверяет почту и вебхуки каждый цикл; напоминания о соревнованиях, разрядах и премиях — один раз за местную дату. Отметки ежедневного запуска сохраняются в `.local/scheduler-state.json`. Для проверки одного прохода используйте `--once`. В Compose запускается отдельный сервис `scheduler`; живые процессы не считаются сохранёнными в облачном снимке.
