# Чекпоинт № 1 · описание решения

Проблема: сведения о спортсменах, заявках, судьях, результатах и разрядах ведутся в разных таблицах и переписках. Документы приходится собирать вручную, сроки легко пропустить.

Решение «ОренКод» объединяет процессы вокруг записи соревнования и подтверждённых результатов. Отличие — связанный путь «заявка → допуск → результат → протокол → история → основание квалификации» с проверкой активной роли, аудитом и прозрачным рейтингом.

## Сценарии MVP

1. Министерство создаёт аккаунт федерации. Спортсмен, тренер и судья регистрируются сами.
2. Федерация создаёт соревнование, одобряет заявку, вносит результат и публикует протокол. Спортсмен видит результат в истории.
3. Спортсмен/подтверждённый тренер подаёт заявку на разряд; федерация сохраняет решение, приказ и сроки.
4. Федерация рассчитывает рейтинг, выбирает сборную и получает документы.
5. Реестр и зачисления дают численность по годам и четырём разрезам. Сроки и решения сопровождаются уведомлениями.

## Стек и дополнительные модули

Python 3.12+, Django, HTML/CSS/JavaScript, REST API. PostgreSQL для сервера, SQLite для локального запуска. JWT для API; OIDC code + PKCE для ФСП ID. Форматы XLSX/DOCX/PDF, Docker Compose, планировщик и Caddy HTTPS.

В проекте представлены Д1–Д12: ФСП ID, интеграции, подготовка/нормативы, апелляции, показатели региона, путь спортсмена, премии, министерство, QR, навигатор и документы судьи. Они отделяются от обязательных пунктов 1–8. Нормативные источники и официальные бланки проверяются по материалам организаторов.

Описание не подтверждает историческую сдачу на 22-м часу. Реализация и ограничения отражаются в матрице требований.
