# API v1 и внешние интеграции (Д2)

Базовый путь — `/api/v1/`. JSON, HTTP-коды ошибок и тело `{"error": ..., "code": ...}`. Списки пагинируются по 25 записей, параметр `?page=2`; ответ содержит `count`, `next`, `previous`, `results`. Машиночитаемая схема: `GET /api/v1/schema/`. Консоль федерации `/integrations/` позволяет выдавать/отзывать партнёрские токены, импортировать файлы и настраивать webhook.

## Авторизация

`POST auth/login/` с `username`, `password`, необязательным `role` возвращает `access`, `refresh`, `active_role`. В запросах: `Authorization: Bearer <access>`. Access живёт 15 минут, refresh — день. `POST auth/refresh/` с `refresh` выдаёт новую пару, предыдущий refresh заносится в blacklist. `POST auth/logout/` отзывает переданный собственный refresh; уже выданный access действует до истечения срока. `POST auth/switch-role/` с `role` выдаёт новую пару после проверки назначенной роли.

Активная роль хранится в JWT и сверяется с актуальными ролями профиля на каждом запросе и при обновлении refresh. Наличие роли федерации в аккаунте само по себе не даёт её прав токену спортсмена. Действия и аудит привязаны к выбранной роли. Самостоятельная регистрация не выдаёт роли федерации или министерства. Роль министерства допускает только чтение календаря, сборных и агрегированных отчётов.

Для браузерных клиентов также поддерживается сессия Django; небезопасные сессионные запросы требуют CSRF. JWT и партнёрский токен передаются только заголовком, не в URL. Для эксплуатации нужен HTTPS.

## Ресурсы

| Метод и путь после `/api/v1/` | Данные / разрешение |
| --- | --- |
| `POST auth/register/` | Поля формы регистрации: username, first_name, last_name, email, password1/2, roles[], birth_date, municipality, disciplines[], start_year, personal_consent; несовершеннолетним guardian_name + guardian_consent |
| `GET/PATCH me/` | Собственный профиль; роли нельзя изменить через самообслуживание |
| `GET/POST athletes/`, `GET/PATCH athletes/ID/` | Общий список без даты рождения и email; личная карточка только владельцу, действующему тренеру и федерации. Создание/редактирование чужого профиля — федерация |
| `GET coaches/`, `GET judges/` | Реестр соответствующей роли |
| `GET/POST competitions/`, `GET/PATCH competitions/ID/` | Чтение календаря; создание/изменение только федерация. Фильтры q, state, discipline |
| `POST competitions/ID/publish/` | Опубликовать соревнование и положение |
| `POST competitions/ID/open-applications/` | Открыть регистрацию с проверкой положения и дат |
| `POST competitions/ID/close-applications/` | Закрыть приём заявок |
| `GET applications/`, `GET competitions/ID/applications/` | Собственные заявки/подопечные либо все для федерации |
| `POST competitions/ID/applications/` | athlete, discipline; возраст, сроки, отстранение и тренерская связь проверяются сервером |
| `PATCH applications/ID/moderate/` | Федерация: status=approved/rejected, comment; причина отклонения обязательна |
| `GET/POST competitions/ID/results/` | application, place, score; запись только федерации по одобренным заявкам после закрытия регистрации |
| `POST competitions/ID/publish-protocol/` | Федерация; все заявки рассмотрены и результаты каждого допущенного участника внесены |
| `GET competitions/ID/protocol/` | Опубликованный протокол в JSON; черновики доступны только федерации |
| `POST competitions/ID/results/import/` | Федерация/партнёр с results:import; JSON `{"results": [...]}` |
| `GET qualifications/`, `POST rank-applications/` | kind для POST задаёт URL: rank; athlete, result, requested_title. Источник — опубликованный результат этого спортсмена |
| `POST judge-category-applications/` | athlete (профиль судьи), requested_title; result не используется |
| `PATCH qualifications/ID/review/` | Федерация: status, review_comment, assigned_on, valid_until, order_number |
| `GET/POST competitions/ID/judge-assignments/` | Назначение: judge, position; чтение — федерация или собственные назначения судьи |
| `GET judge-assignments/` | Назначения текущего судьи |
| `GET/POST coach-links/`, `PATCH coach-links/ID/` | Тренер запрашивает athlete+discipline; только спортсмен активирует связь, стороны могут приостановить/завершить |
| `GET rating/` | season, discipline, age_min, age_max, min_rank; исходные результаты, баллы и коэффициент |
| `GET/POST national-team/`, `GET national-team/ID/` | Создание федерацией: season, discipline, age_min/max, min_rank, members[] из допустимого рейтинга |
| `GET reports/athletes-count/` | Федерация/министерство: year_from, year_to, discipline, org, age_min, age_max, municipality; все фильтры применяются совместно, как в веб-интерфейсе |
| `GET reports/athlete-competitions/ID/` | История спортсмена с проверкой доступа к личной карточке |
| `GET documents/KIND/ID/FMT/` | Файл XLSX/DOCX/PDF; KIND protocol/team/athlete/census/consent. Права совпадают с веб-экспортом |
| `GET notifications/`, `PATCH notifications/ID/read/` | Только собственные уведомления |
| `GET audit-log/` | Журнал, только федерация |
| `GET/POST dictionaries/KIND/` | disciplines, organizations, entries, document-layouts; запись только федерация. rating-rules доступны для чтения, изменение через интерфейс федерации |

HTML и JSON действия используют общие формы и обработчики бизнес-процессов. Поэтому через API нельзя обойти согласие тренерской связи, выдать результат неодобренной заявке или изменить опубликованный протокол. PATCH соревнования использует ту же блокировку строки, что и публикация.

## Партнёрские токены и импорт

Федерация выдаёт токен в `/integrations/`, выбирает срок 1–365 дней и минимальные разрешения: `read:competitions`, `read:results`, `results:import`. Полное значение показывается один раз; в БД сохраняется SHA-256-хэш, префикс для узнавания и метаданные. Заголовок: `Authorization: Partner fsp_...`. Партнёр не получает доступ к профилям, смене роли или административным действиям. Отзыв токена, истечение срока и отзыв роли федерации у создателя немедленно прекращают доступ.

Импорт через API:

```json
{"results":[{"application":17,"place":1,"score":"950.50"},{"application":18,"place":2,"score":"900"}]}
```

Через интерфейс можно загрузить JSON такого вида/массив либо CSV UTF-8 с заголовком `application,place,score`, до 2 МБ. Все три поля обязательны в каждой строке. ID заявки и место — положительные целые JSON-значения либо целочисленные строки CSV; дробные числа, `1.0` и логические значения отклоняются без усечения. Баллы — конечное неотрицательное число с максимум двумя десятичными знаками и восемью цифрами целой части. Пропущенные баллы не заменяются нулём; `NaN`, бесконечность, `true`, пустые значения и лишняя точность отклоняются. Явно заданный ноль допустим.

ID заявки однозначно задаёт спортсмена и дисциплину. Проверяются одобрение заявки в выбранном соревновании, уникальность участника и места по дисциплине. Импорт атомарный: одна ошибка откатывает все строки и сохраняет прежние результаты. Разрешена согласованная перестановка мест в импортируемом наборе. Опубликованные результаты не перезаписываются. Для ошибочного JSON API возвращает HTTP 400 с `code: validation_error`.

## Webhook

1. В настройках развёртывания задайте точный список внешних hostname `INTEGRATION_WEBHOOK_ALLOWED_HOSTS`. По умолчанию он пуст: внешние отправки запрещены.
2. Федерацией создайте подписку с HTTPS URL на порту 443 и событиями `competition.published`, `competition.opened`, `application.approved`, `protocol.published`. Сохраните показанный один раз ключ подписи. В БД он хранится зашифрованным ключом приложения; при смене DJANGO_SECRET_KEY подписки нужно перевыпустить.
3. Бизнес-действия сохраняют событие и очередь в одной транзакции. `competition.published` означает публикацию соревнования с положением; `competition.opened` — открытие регистрации; `protocol.published` — публикацию результатов. Подписка на одно событие не получает другое вместо него.
4. Планировщик вызывает `python manage.py deliver_webhooks`. До 50 сообщений за проход, 5 попыток с экспоненциальной задержкой. Неуспех внешней системы не откатывает соревнование. Статус и число попыток видны в консоли.

Получатель проверяет `X-FSP-Signature: sha256=...` как HMAC-SHA256 от `X-FSP-Timestamp + "." + сырое тело`. Используйте постоянное по времени сравнение, допустимое окно времени (например, 5 минут) и дедупликацию `X-FSP-Event-ID`: повторная доставка допустима. Пример тела:

```json
{"id":"UUID","event":"protocol.published","created_at":"2026-10-27T10:00:00+00:00","entity":"competition:12"}
```

TLS и сертификаты проверяются. Перед каждой отправкой DNS проверяется на отсутствие внутренних/loopback/link-local адресов; соединение закрепляется на проверенный публичный IP с исходным SNI. Redirect не выполняется. Очередь не хранит тела ответов партнёра и секреты в ошибках. Реальный внешний endpoint не подключается автоматически; автоматические тесты проверяют подписи и повторы без отправки сообщений во внешние системы.

## Проверка

`python manage.py test integrations` проверяет реальный JWT-цикл соревнования, права активной роли, отзыв ролей/токенов, refresh rotation, CSRF сессии, защиту чужих профилей, атомарность импорта, HMAC, очередь/повторы и блокировку SSRF. Настройка реального партнёра выполняется владельцем среды с его hostname и безопасно переданным токеном.
