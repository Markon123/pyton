# Исправления и рабочая схема аккаунтов · 28 октября 2026

По уточнению владельца проекта основной аккаунт — министерство. Обычная установка создаёт его в БД до открытия интерфейса. Министерство создаёт федерации; самостоятельно регистрируются только спортсмены, тренеры и судьи. Это уточнение изменяет прежнюю модель министерства, имевшего только чтение сводок: теперь ему дополнительно доступно управление служебными аккаунтами, без изменения спортивных результатов.

## Убран учебный запуск

- На странице входа нет блока выбора демоаккаунтов, общего пароля и автоматического заполнения.
- Убраны постоянные подписи о демоверсии. Рабочие документы не помечаются вымышленными.
- Стартовые файлы — start.bat/start.sh. Обычный запуск не вызывает seed_*.
- Чистая база .local/platform.sqlite3 содержит только главную учётную запись и справочники. Вымышленных спортсменов, организаций и соревнований нет.
- Временный пароль министерства уникален для установки. Он хранится в БД как хэш, а первоначальные данные доступны владельцу в закрытом .local/first-access.txt. Повторный запуск их не сбрасывает.
- При первом входе служебные аккаунты меняют пароль и дают согласие. API не позволяет пропустить этот шаг. Федерация не назначает себе или другим служебные роли.

## Проверено

- 203 теста прошли на SQLite, 203 — на PostgreSQL 16.15.
- Проверены установка и повторный запуск: один главный аккаунт, отсутствие вымышленных участников/стартов, сохранность пароля.
- Через настоящий браузер пройден путь министерство → создание/активация федерации → самостоятельная регистрация спортсмена → соревнование → заявка → одобрение → результат → предварительный документ → опубликованный PDF → история спортсмена.
- В этой браузерной проверке выполнен 21 проход страниц на ширинах 360/768/1440, без переполнения страницы и ошибок JavaScript.
- SMTP проверен настоящим отдельным локальным приёмником. Экран доставки позволяет сотруднику запросить тест на собственную почту; факт получения проверяется отдельно.
