# Чекпоинт № 2 · сквозной сценарий

Для чекпоинта выбран один полный сценарий: **федерация создаёт соревнование → спортсмен подаёт заявку → федерация одобряет заявку и вносит результат → публикуется протокол → результат появляется в истории спортсмена**. Это соответствует требованию показать 1–2 сценария; второй сценарий не обязателен.

## Материалы для демонстрации

- [Видео сквозного сценария — MP4, 2 минуты 5 секунд](checkpoint-2.mp4). [Открыть или скачать видео с GitHub](https://github.com/Markon123/pyton/raw/refs/heads/main/docs/checkpoint-2.mp4).
- [Протокол соревнования — PDF](checkpoint-2-protocol.pdf), получаемый через кнопку выгрузки в приложении.
- [Скрипт повторной записи](../scripts/record_checkpoint2.cjs).

Видео записывает действия в работающем приложении с поясняющими титрами, без голосового сопровождения. В записи используются разные учётные записи `federation` и `athlete`, а не только переключение роли одного пользователя. После выгрузки отдельно показана первая страница фактически скачанного PDF, преобразованная в изображение без изменения содержимого. Все участники, организации, положение и результаты демонстрационные. Протокол помечен как демонстрационный и не является официальным документом федерации.

`demo.webm` в этой же папке — отдельный обзор разделов платформы. Для данного чекпоинта предназначен именно `checkpoint-2.mp4`.

Проверка записи: длительность MP4 — 124,88 секунды, формат H.264. При записи автоматически проверены успешные переходы форм, статусы заявки, содержимое скачанного PDF и точная строка результата в истории спортсмена; ошибок браузера нет. Дополнительно прошли два существующих теста: полный цикл соревнования и запрет публикации неполного протокола/изменения уже опубликованных результатов.

## Повторить вручную

Запустите проект по [инструкции для Windows, macOS и Linux](local-launch.md). Лаунчер применяет миграции и добавляет вымышленные данные командой `seed_full_demo`. Для обеих демонстрационных учётных записей пароль — `FspDemo2026!`.

Выполните шесть шагов из таблицы. Используйте выход и повторный вход либо отдельные браузерные профили для федерации и спортсмена. В новом соревновании укажите сегодняшнюю дату начала и окончания; регистрацию откройте с даты не позже сегодняшней и завершите сегодня. Тогда заявку можно подать сразу и пройти весь учебный сценарий без ожидания. Для открытия регистрации нужно загрузить положение в PDF или DOCX. Возрастной диапазон должен включать спортсмена; у демонстрационного `athlete` есть дисциплина «Программирование алгоритмическое».

История находится в **«Мой профиль» → «Спортивная карточка» → «История выступлений»**. После публикации протокола результат попадает туда автоматически. Дополнительные проверки и продолжение сценария до заявки на разряд описаны в [сценарии приёмки № 1](acceptance.md#1-соревнование-протокол-и-квалификация).

## Повторная запись

Скрипт использует Node.js и Playwright. Зависимости для записи устанавливаются отдельно от Python-приложения:

```bash
npm install --prefix .local/checkpoint2-tools playwright@1.58.2
```

Для самостоятельной записи используйте отдельную демонстрационную базу через `DATABASE_PATH`, примените миграции и `seed_full_demo`, затем запустите приложение на локальном порту `8012`. Подготовьте действительный демонстрационный DOCX положения в `.local/checkpoint2/regulation.docx`. Такой запуск не изменяет основную базу проекта.

По умолчанию скрипт ожидает Playwright в `.local/checkpoint2-tools/node_modules/playwright`, сервер на локальном порту `8012`, положение в `.local/checkpoint2/regulation.docx` и Chromium в `/usr/bin/chromium`. Настройки можно изменить через `PLAYWRIGHT_MODULE`, `CHECKPOINT_BASE_URL`, `CHECKPOINT_REGULATION` и `CHROMIUM_PATH`. Рабочие результаты сохраняются в `.local/checkpoint2`; другой каталог задаётся через `CHECKPOINT_OUTPUT_DIR`.

Для формирования MP4, проверки и просмотра PDF нужны `ffmpeg`, `pdftotext` и `pdftoppm`. Средство записи Playwright устанавливается его штатной командой `node .local/checkpoint2-tools/node_modules/playwright/cli.js install ffmpeg`; можно использовать и уже установленный системный FFmpeg. Отключать проверку загружаемых файлов не требуется. После подготовки сервера и положения выполните:

```bash
node scripts/record_checkpoint2.cjs
ffmpeg -i .local/checkpoint2/checkpoint-2.webm -c:v libx264 -crf 23 -pix_fmt yuv420p -movflags +faststart -an .local/checkpoint2/checkpoint-2.mp4
```

Конкретные шаги автоматизации и проверки результата находятся в [скрипте записи](../scripts/record_checkpoint2.cjs). Скрипт сохраняет исходную запись WebM, PDF и сведения о проверке. Проверяйте длительность новой записи: заданный интервал — 2–3 минуты. Итоговый MP4 для сдачи находится по ссылке выше.

Публичный стенд для сдачи этого чекпоинта не требуется, если предоставлено видео указанной в задании длительности. Сам файл видео не означает, что приложение размещено на публичном хостинге.
