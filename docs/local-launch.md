# Запуск рабочей платформы

На Windows установите Python 3.12+ с Add Python to PATH, распакуйте проект и запустите **start.bat**. На macOS/Linux: **bash start.sh**. Первая установка требует интернет. Браузер открывается после проверки готовности; окно запуска не закрывайте.

Лаунчер создаёт .venv, устанавливает закреплённые зависимости, применяет миграции, подготавливает справочники и единственный главный аккаунт министерства. Участники и соревнования не добавляются. База по умолчанию — .local/platform.sqlite3.

## Первый вход

Откройте **.local/first-access.txt** в папке проекта. Там логин ministry и случайный временный пароль этой установки. Пароль не печатается в журнале и хранится в БД в виде хэша. При первом входе задайте свой пароль и подтвердите согласие. Повторный запуск пароль не сбрасывает.

Министерство создаёт федерации через «Аккаунты федераций». Сотрудник федерации также меняет временный пароль при первом входе. Спортсмены, тренеры и судьи регистрируются сами. Демоаккаунтов и автоматического заполнения входа нет.

Для автоматизированной установки можно безопасно задать FSP_MINISTRY_USERNAME, FSP_MINISTRY_EMAIL, FSP_MINISTRY_PASSWORD. При заданном пароле файл доступа не создаётся. У существующего главного аккаунта переменные пароль не меняют. Оператор установки может восстановить свой доступ командой **python manage.py changepassword ministry** в активированном окружении.

## Если запуск не получается

- Полностью извлеките архив: запускать BAT внутри ZIP нельзя.
- Если Python не найден, установите его с Add Python to PATH.
- Первую установку не прерывайте: зависимости загружаются из интернета.
- При ошибке окно Windows останется открытым; причина также записана в .local/launcher.log. Пароли из first-access.txt в чат не копируйте.
- Если порт занят, завершите предыдущее своё окно либо задайте FSP_PORT (1024–65535). Лаунчер чужие процессы не завершает.

Проверка без запуска сервера: **python scripts/launch.py --check-only**. Для готового окружения задайте FSP_VENV_DIR, например /workspace/.venvs/pyton. Процессы после восстановления облачной среды запускают заново.

Старые start-demo.bat/start-demo.sh/scripts/launch_demo.py являются совместимыми входами в рабочий запуск; тестовые данные они не добавляют.
